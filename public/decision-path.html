The Decision Path

When you type a prompt into this repository, most of what happens next is not the AI deciding. It is a short chain of small programs that read the AI's intended command, and pass it, edit it, or stop it — before the command ever runs. This page shows that chain, the map the AI consults instead of reading your files, and the 359-table data lineage underneath it all.

01 PROMPT

Press Enter, and four checkpoints wake up

Think of it like posting a letter. You write it, but before it reaches the desk it passes a mail room: one clerk staples a standing note to the front, another refuses anything addressed to a forbidden street, a third quietly rewrites the envelope so the reply comes back smaller.

Pick a request below and watch it travel. Every checkpoint is a real file in this repository, and every verdict is decided by plain text matching — no model involved.

Choose a request

The punchline for a non-programmer: the safety of this system does not rest on the AI choosing well. It rests on six string patterns in a 38-line shell script that runs before the AI's command reaches the computer.
02 MAP

The whole codebase, as neighbourhoods

Reading a repository file by file is like learning a city by walking every street. Instead this repository keeps a map: each of the 3,460 things in the code is a dot, each relationship a line, and dots that talk to each other constantly get grouped into a neighbourhood.

Below are the 36 largest of the 248 neighbourhoods. Circle size is how many things live there; a line means the two neighbourhoods reference each other. Hover or tap a circle to see what is inside it.

03 LINEAGE

One business number, and everything holding it up

The map in the previous section is made of code. This one is made of data. This repository builds 396 tables that feed finance and sales reporting for thirteen different accounting and commerce systems, and every one of those tables is computed from other tables, which are computed from other tables, and so on back to the raw exports.

Pick a finished figure below. The diagram shows every single thing it stands on — read left to right, from the raw tables the source systems dump out, to the number someone actually looks at.

The thirteen source systems

Each connector brings its own raw tables and its own adapter layer. They are wildly uneven — one system accounts for nearly half the project.

This section reads a different source — and that turned out to matter. The two diagrams above read the repository’s code graph. This one reads dbt’s own build manifest, and building this page is what exposed why that distinction is not cosmetic: the code graph held only 104 of the 688 table-to-table links and was missing 216 tables outright. That is a failure mode this repository’s own manual names — rebuilding the code graph after merging dbt lineage deletes it, because there is no SQL parser to re-extract it from. Re-running the merge restored all 688 of 688, and the isolated-node count fell from 353 to 94. The diagram still draws from the manifest, which is the copy that cannot silently lose an arrow.
04 LOOKUP

What the AI actually gets to see

When the AI asks a question, the map is not handed over whole. Three steps happen. First, the question's words are matched to starting dots. Second, the search walks outward exactly two steps — friends, and friends of friends, then stops. Third, and this is the part everyone underestimates: the result is cut to fit a budget, keeping the best-connected dots and throwing the rest away.

The real question below reaches 176 dots. Drag the budget to see how many survive to be read. The numbers on the readout are the actual output of the command, not an illustration.

graphify query "how does the TOON serializer connect to the graphify hook"

The drawing holds the 65 best-connected of the 176 dots this search reaches — enough to see the shape without a hairball. The survivor count and character count in the readout are measured from the real command; solid dots are the ones that would fit inside that budget.
This is why a vague question gets a vague answer. At a 400-token budget the search finds 176 relevant things and shows 11 of them. The fix is not a bigger model — it is a narrower question.
05 SQUEEZE

Same answer, fewer words

The AI is charged by the word, so the answer is re-typed on the way back. The left side repeats src=, loc= and community= on every single line. The right side says those column names once at the top and then just lists rows — like a spreadsheet instead of a stack of forms.

The saving grows with the number of rows, because the repeated part is what gets deleted: on a 28-finding report elsewhere in this repo the same rewrite cuts 7,447 characters to 2,624 — 65% smaller. On a four-line output it makes things bigger, which is why the rewrite is switched on per command rather than globally.

  


  
  

    06 STOP
    
Six patterns that end the conversation

    
The guardrail does not evaluate intent, read context, or ask the model anything. It matches the start of the command against six patterns and exits with an error code. Everything else is allowed through untouched.

    

      
    
        
  • git push …Nothing leaves this machine without a human doing it.
    • 
        
  • git reset --hard …Throws away uncommitted work with no undo.
    • 
        
  • git clean -fDeletes untracked files outright — nothing to recover from.
    • 
        
  • git branch -D …Force-deletes a branch even when its work is unmerged.
    • 
        
  • git checkout .Silently reverts every edited file in the folder.
    • 
        
  • git restore .The newer spelling of the same loss.

    07 VERDICT
    
Where the decisions actually live

    
Three different kinds of decision run in the space between your prompt and an answer, and only one of them is the AI's.

    

      
    
        
  • rulesFixed and inspectable. The guardrail and the rewriter are text matching in two small scripts. They behave the same on every run, and you can read them in a minute.
    • 
        
  • structureComputed from the code. Which dots are neighbours, and which survive the budget, comes out of the map — rebuilt from the source, so it cannot drift for long.
    • 
        
  • judgementThe model's part. Choosing what to ask, how to phrase it, and what to do with the answer. Real, but far smaller than it looks — and it is fenced in by the other two.
