# skill-map Rules

Binding rules for the skill-map integration in this repository.

## Determinism

1. **No LLM verb, ever.** `sm jobs *`, `sm agent *`, `sm findings *`, and
   `sm refresh` reach skill-map's probabilistic layer and are out of scope for
   this repository. The allowlist in `scripts/skill_map_scan.py` enforces this
   and `tests/test_skill_map_pack.py` pins it.
2. **Every scripted invocation goes through the wrapper.** A direct `sm` call in
   a script, hook, or workflow bypasses the allowlist, the version pin, and the
   telemetry-off environment. Interactive use by a human is fine.
3. **The CLI version stays pinned.** Analyzers decide which issues exist, so an
   unpinned upgrade moves the finding counts — and any gate keyed to them —
   with no diff to point at.
4. **Unavailable is not failed.** No Node means exit `3` and a recorded `skip`.
   A check must never go red because a runner lacks an optional toolchain.

## Interpretation

5. **Halve the counts before reacting.** Pack and activated mirror are both
   scanned, so every defect is reported twice. A finding present in only one
   tree is drift, and a different problem.
6. **Fix the pack, never the mirror.** `.claude/` is generated by
   `scripts/activate_skill_stack.sh`.
7. **A broken reference inside prose is not a broken reference.** This analyzer
   cannot tell an illustrative path from a dead link. Where it disagrees with
   `tests/test_docs_links.py`, the test wins.
8. **Accepted findings are written down, not rediscovered.** The
   `senior-analytics-engineer` collision, the `/review` shadowing, and the
   agent `tools`-as-string warnings are documented exceptions. Re-reporting
   them as new findings is noise.

## Change discipline

9. **A new collision or frontmatter parse error is a defect in the change that
   introduced it.** Both fail silently at runtime — the harness loads something
   other than what you meant — which is the whole reason this scan exists.
10. **Scope is the harness.** Application-code questions go to `graphify` under
    the Graphify-first rule in `CLAUDE.md`. Two graphs, two purposes.
