# State, Deferral, and CI/CD

How dbt knows what changed, and how to build a CI pipeline that stays enabled.

## The core idea

dbt writes a full description of the project into `manifest.json`. Given the **previous**
manifest, dbt can compute what changed — so CI builds only the changed slice and reads
everything else from production.

Two flags do this:

- **`--state <dir>`** — where the previous `manifest.json` lives.
- **`--defer`** — resolve `ref()`s to nodes *not in the current selection* against the state
  manifest's relations instead of building them.

```bash
dbt build --select state:modified+ --defer --state prod/ --target ci
```

A PR touching one mart builds one model and reads real production upstream data. Seconds
instead of an hour.

## `state:` selectors

| Selector | Matches |
|---|---|
| `state:new` | absent from the state manifest |
| `state:modified` | any change — body, config, tests, descriptions, macros used |
| `state:modified.body` | SQL body only |
| `state:modified.configs` | config only |
| `state:modified.relation` | database/schema/alias changed |
| `state:modified.persisted_descriptions` | description changed with `persist_docs` on |
| `state:modified.macros` | a macro the node depends on changed |
| `state:modified.contract` | contract changed — the breaking-change gate |
| `state:old` | in state but not in the current project |

`state:modified` is deliberately broad: it includes description-only edits, which is usually
what you want (a `persist_docs` change is a real warehouse change). Narrow with
`state:modified.body+` if the noise is genuinely a problem, accepting that config-only
changes then go unvalidated.

`state:modified+` — with the `+` — is what you almost always want. Without it, changed models
build but their downstream dependents never get validated against the change.

## The mistakes

**`--state` pointing at the current `target/`.** It must be the *previous* (production)
manifest. Pointed at the current one, `state:modified` matches nothing and CI silently
validates nothing at all. This is the single most common slim-CI failure and it fails
*green*.

**A stale state manifest.** Generated by a different dbt version or a different project,
`state:modified` matches everything and CI rebuilds the world. Regenerate the production
manifest after every dbt upgrade.

**`--defer` on a selected node.** Defer only applies to nodes *not* in the selection. A
selected model always builds.

## `--defer` semantics

| Situation | Resolves to |
|---|---|
| Node is selected | built in CI |
| Node is not selected, exists in state, exists in the CI schema | the CI relation |
| Node is not selected, exists in state, not in the CI schema | the **production** relation |
| Node is not selected, absent from state | error |

`--favor-state` forces the state relation even when a CI one exists — useful when a stale CI
schema from a previous run would otherwise be preferred.

## Artifact storage

The piece teams skip. Without it, slim CI, freshness monitoring, and breaking-change
detection all stop working at once.

```bash
# End of every production run — including failures
aws s3 cp target/manifest.json     s3://dbt-artifacts/prod/manifest.json
aws s3 cp target/run_results.json  s3://dbt-artifacts/prod/run_results.json
aws s3 cp target/sources.json      s3://dbt-artifacts/prod/sources.json
aws s3 cp target/catalog.json      s3://dbt-artifacts/prod/catalog.json

# Dated copy for regression comparison
aws s3 cp target/run_results.json "s3://dbt-artifacts/history/$(date +%F)/run_results.json"
```

| Artifact | Enables |
|---|---|
| `manifest.json` | `state:modified`, `--defer`, breaking-change detection, every script here |
| `run_results.json` | performance regression comparison, `dbt retry`, alerting |
| `sources.json` | freshness monitoring |
| `catalog.json` | the docs site, real column types for contracts |

Upload on failure too — a failed run's `run_results.json` is exactly what you need to
diagnose it.

## A full CI pipeline

```yaml
# .github/workflows/dbt_ci.yml
name: dbt CI
on: pull_request

concurrency:
  group: dbt-ci-${{ github.head_ref }}
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    env:
      SNOWFLAKE_ACCOUNT: ${{ secrets.SNOWFLAKE_ACCOUNT }}
      SNOWFLAKE_USER:    ${{ secrets.SNOWFLAKE_CI_USER }}
      SNOWFLAKE_KEY:     ${{ secrets.SNOWFLAKE_CI_KEY }}
      DBT_CI_SCHEMA: dbt_ci_pr_${{ github.event.number }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: {python-version: '3.11'}

      - run: pip install -r requirements.txt

      - name: Fetch production artifacts
        run: |
          mkdir -p prod
          aws s3 cp s3://dbt-artifacts/prod/manifest.json prod/manifest.json

      - run: dbt deps

      # --- Structural gates: seconds, no warehouse ---
      - run: dbt parse
      - run: python scripts/dbt_project_auditor.py --manifest target/manifest.json --strict
      - run: python scripts/contract_breaking_change_detector.py
               --base prod/manifest.json --head target/manifest.json --strict
      - run: python scripts/test_coverage_reporter.py --manifest target/manifest.json
               --layer marts --min-coverage 0.9 --strict
      - run: python scripts/semantic_layer_validator.py --path models/ --strict

      # --- Schema validation: zero data scanned ---
      - run: dbt build --select state:modified+ --defer --state prod/ --empty --target ci

      # --- Real build of the changed slice ---
      - run: dbt build --select state:modified+ --defer --state prod/ --target ci --warn-error

      # --- Lineage diagram in the PR ---
      - name: Post DAG comment
        if: always()
        run: |
          python scripts/model_dependency_analyzer.py --manifest target/manifest.json \
              --changed-vs prod/manifest.json --mermaid > dag.md

      - name: Drop the CI schema
        if: always()
        run: dbt run-operation drop_ci_schema --args "{schema: $DBT_CI_SCHEMA}" --target ci
```

Order matters: the free checks run first, so a missing test fails in ten seconds rather than
after a twenty-minute build.

### `--empty`

```bash
dbt build --select state:modified+ --defer --state prod/ --empty
```

Builds every selected model with `limit 0`. Validates that the SQL compiles, runs, and
produces the right schema — while scanning no data. The cheapest possible CI check, and it
catches most breakage. Run it before the real build.

### CI schema cleanup

```sql
-- macros/drop_ci_schema.sql
{% macro drop_ci_schema(schema) %}
    {% do run_query("drop schema if exists " ~ target.database ~ "." ~ schema ~ " cascade") %}
    {% do log("Dropped " ~ schema, info=true) %}
{% endmacro %}
```

Run it in an `if: always()` step. CI schemas accumulate until someone hits a quota.

## Production deployment

```yaml
# .github/workflows/dbt_prod.yml
name: dbt production
on:
  schedule: [{cron: '0 * * * *'}]
  workflow_dispatch:

jobs:
  run:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: {python-version: '3.11'}
      - run: pip install -r requirements.txt
      - run: dbt deps

      - name: Source freshness gate
        run: |
          dbt source freshness --target prod || true    # don't fail on the dbt exit code
          python scripts/source_freshness_monitor.py --sources target/sources.json \
              --manifest target/manifest.json --strict   # this decides

      - run: dbt snapshot --target prod
      - run: dbt build --target prod --threads 12 --exclude tag:nightly
      - run: dbt docs generate --target prod

      - name: Upload artifacts
        if: always()
        run: |
          aws s3 cp target/manifest.json    s3://dbt-artifacts/prod/manifest.json
          aws s3 cp target/run_results.json s3://dbt-artifacts/prod/run_results.json
          aws s3 cp target/sources.json     s3://dbt-artifacts/prod/sources.json
          aws s3 cp target/catalog.json     s3://dbt-artifacts/prod/catalog.json

      - name: Report
        if: always()
        run: python scripts/run_results_analyzer.py --run-results target/run_results.json
               --manifest target/manifest.json --top 10
```

`if: always()` on the upload step is important — a failed run's artifacts are the ones you
need most.

## Orchestration beyond CI

| Tool | Fit |
|---|---|
| cron + shell script | one project, one cadence. Genuinely fine — do not over-engineer |
| GitHub Actions schedule | small teams already on GitHub; watch the job timeout |
| Airflow + `astronomer-cosmos` | dependencies on non-dbt tasks; renders each model as an Airflow task |
| Dagster + `dagster-dbt` | asset-oriented; models become assets with cross-tool lineage |
| Prefect / Kestra / Argo | similar; use what the platform team already runs |

**One task for the whole build** is simple but retries everything. **One task per model**
(Cosmos, dagster-dbt) gives granular retry and per-model alerting at the cost of scheduler
overhead. Start with one task; split when a failure in one model genuinely should not block
unrelated branches.

`dbt retry` makes the single-task pattern much more tolerable — it re-runs only what failed.

## Environments

| Target | Database / schema | Run by |
|---|---|---|
| `dev` | `ANALYTICS_DEV` / `dbt_<username>` | a developer |
| `ci` | `ANALYTICS_CI` / `dbt_ci_pr_<n>` | CI, dropped after |
| `prod` | `ANALYTICS` / `marts`, `staging` | the orchestrator only |

Non-negotiables: personal dev schemas; ephemeral CI schemas; nobody runs `--target prod` from
a laptop; snapshots write to a shared non-suffixed schema in every environment.

## Troubleshooting

| Symptom | Cause |
|---|---|
| `state:modified` matches everything | state manifest from a different dbt version or project |
| `state:modified` matches nothing after a real change | `--state` points at the current `target/` |
| CI passes but production breaks | CI did not select the affected downstream — use `state:modified+` with the `+` |
| `--defer` still rebuilds upstream | the upstream node is *selected* |
| `Compilation Error: node not found` with defer | the node is absent from the state manifest — regenerate it |
| CI slower every week | CI schemas not being dropped |
| Selector works locally, fails in CI | `dbt deps` did not run |
| Tests fail on unbuilt models in CI | set `indirect_selection: cautious` |

## Anti-patterns

- CI that rebuilds the whole project. It gets disabled within a month.
- No stored production artifacts.
- `--state` pointing at the current `target/`.
- `state:modified` without the trailing `+`.
- Running production from a laptop.
- One shared dev schema.
- CI schemas never dropped.
- Uploading artifacts only on success.
- A twelve-clause selector in a cron job instead of a named entry in `selectors.yml`.
