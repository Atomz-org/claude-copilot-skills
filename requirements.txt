# Python dependencies for code-skills.
#
# The analyzers in scripts/ are standard-library by default: a fresh checkout
# runs them with nothing installed. Everything below is an *optional* accelerator
# or parser, each guarded by a try/except ImportError so its absence degrades a
# run rather than failing it. Installing this file turns those degraded paths on.
#
#   pip install -r requirements.txt

# --- parsers and accelerators -------------------------------------------------

# Column-level lineage (scripts/dbt_column_lineage.py, scripts/dbt_sample_build.py)
# and the `seeds` stage of scripts/use_case_sync.py. Without it those stages report
# `skip` with a reason instead of silently emitting an artifact with no column
# mappings.
#
# Pinned to the 30.x line on purpose. sqlglot 30 renamed the `from` argument to
# `from_`; a resolver reading only the old key returns `unresolved` for every edge
# without erroring, which is the failure mode tests/test_dbt_column_lineage.py
# exists to catch. Moving major versions means re-running that suite first.
sqlglot>=30.14.0,<31

# JSON accelerator for reading dbt artifacts (scripts/_manifest.py). manifest.json
# is ~3 MB and is parsed by most analyzers; absence is the normal case and costs
# only time.
orjson>=3.11.9

# WrenAI semantic layer CLI (scripts/wren_context_sync.py and the `wren` stage of
# scripts/use_case_sync.py). Source is pinned as a submodule at external/WrenAI;
# this wheel is the runtime. Without it the `wren` stage reports `skip` with a
# reason. Pinned exactly: the stage shells out to the CLI, and CLI surface moved
# between 0.x minors. Bump together with the external/WrenAI submodule SHA.
# wrenai requires sqlglot>=29, satisfied by the 30.x pin above. The [mcp] extra
# powers `wren serve mcp` — the per-use-case MCP server wren/mcp.json points at.
wrenai[mcp]==0.13.2
# wrenai 0.13.2 imports mcp.server.fastmcp, which mcp 2.0 removed, and its extra
# declares no upper bound — without this pin a fresh install boots a server that
# dies on import (fix staged at external/patches/wrenai-mcp-extra-upper-bound.patch).
mcp<3

# --- MetricFlow (installs into the DBT venv, not this one) --------------------
#
# Rule 45's validator and local query loop for the semantic layer. NOT listed as
# an installable line because it would drag dbt-core into this venv; the dbt
# environment is managed separately (see artifacts/refresh.sh's DBT_BIN ladder).
# Install it beside dbt:
#
#   .venv-dbt/bin/pip install "dbt-metricflow[dbt-duckdb]==0.8.2" "dbt-core==1.9.9"
#
# Measured on install (2026-08-06): resolves metricflow 0.207.3, keeps dbt-core
# at 1.9.9, and moves dbt-duckdb 1.10.1 → 1.9.6 (the 1.9-series adapter pairing);
# the full suite passes on the downgraded adapter. Without mf, the agreement gate
# (tests/test_metricflow_wren_agreement.py) skips with the install command named —
# serving never needs mf, because Wren executes the compiled views.

# --- tests --------------------------------------------------------------------

# The suite itself. CI installs this separately; listed here so one command gives
# a working development environment.
pytest>=9.1.1

# Parallel test execution. The suite is subprocess-bound — nearly every test shells
# out to a script in scripts/ — so it ran 97s at 70% CPU on a 10-core machine.
# With this installed it runs in 34s; without it, serially, and nothing fails.
# `_pytest_parallel.py` (named from pytest.ini's addopts) turns it on only when the
# import succeeds, so this stays a genuine accelerator rather than a hard dependency.
pytest-xdist>=3.8.0

# Parses the generated Turtle in tests/test_ontology_generator.py to assert the
# .ttl and index.json projections agree. Test-only: nothing in scripts/ imports it,
# and the generator is deliberately written not to need a parser at runtime.
rdflib>=7.6.0
