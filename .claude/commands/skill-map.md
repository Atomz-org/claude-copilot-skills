# `/skill-map`

Map the harness and report what is structurally wrong with it.

Load the `harness-mapping` skill for the analyzer reference and the accepted-findings
list before interpreting anything below.

## Run

```bash
python scripts/skill_map_scan.py --summary
```

Exit `3` means no `sm` CLI resolved on this machine (needs Node, or a set
`SKILL_MAP_BIN`). That is a "cannot run", not a failure — say so and stop rather
than reporting a clean harness.

## Report

Lead with the structural errors, in this order:

1. **`name-collision`** — two entries answer to one name; dispatch is undefined.
2. **`frontmatter-parse-error`** — invalid YAML; strict parsers drop the entry.
3. **`reference-broken`** — dead pointers, after discarding prose examples.
4. **`name-reserved`** — shadowed by a Claude Code built-in.

Then the shape: node counts by kind, and anything that moved since the last run.

## Two rules that decide whether your reading is right

**Halve the counts.** Every pack asset exists twice — once under
`skill-packs/<pack>/` and once in the activated `.claude/` mirror — so each
defect is reported twice. A finding that appears in only one tree means the pack
and mirror have drifted, which is a separate and more interesting problem.

**Fix the pack, never the mirror.** `.claude/` is generated by
`scripts/activate_skill_stack.sh`; an edit there is reverted on the next
activation.

## Known and accepted

- `senior-analytics-engineer` collides as both an agent and a skill. Documented
  in `CLAUDE.md` as a compatibility alias. Not a bug.
- `/review` is shadowed by the Claude Code built-in.
- `/tools must be array` on agents — Claude Code accepts the string form.

Do not report these as new findings. Anything else at error severity is a defect
in the change that introduced it.

## Scope

This maps the **harness**. For application code, use `graphify` per the
Graphify-first rule in `CLAUDE.md`. Different graphs; neither substitutes for
the other.

Never run `sm jobs`, `sm agent`, `sm findings`, or `sm refresh` — that is
skill-map's LLM layer, and this repository's integration is deterministic by
construction. Detail lives in the `harness-mapping` skill.
