Business context

Objective · users · value · metrics

The engagement is multi-tenant financial analytics: nineteen ERP, CRM and commerce systems land in one warehouse, and a tenant may have any combination of them enabled. Every connector answers roughly the same questions — what did we sell, to whom, against which account — under nineteen different sets of column names.

Conformance is therefore the whole product, and conformance drift is invisible by construction: an adapter that renames one column breaks a union only when two connectors are enabled at once, so the connector's own build passes and the failure waits for a tenant with both.

Users

The decision this architecture encodes

Adding a connector has exactly one genuinely unknown input: the raw table's column list. Everything else in the project is a rename of it. That one unknown was also the only thing nobody had written down — measured at the start, 200 source tables declared, zero of them declaring their columns. The raw schema existed only inside whatever somebody had hand-typed into a staging model, which is why drift was detectable downstream but not preventable upstream.

Data flow

Sources → conformance → serving

Three lanes, and the arrow between the first two runs both ways. Meaning is derived from the warehouse — dbt's own manifest.json is the input to every ontology artifact. The business layer is then generated back from that meaning, which is what closes the loop the middle lane exists to hold.

  • Data / raw layer
  • Processing / transformation
  • Semantic / generated meaning
  • Serving / consumer output

Solid arrows are generated dependencies; the dashed left rail is WrenAI's own dbt importer, which owns the mechanical layer while the bridge adds only what dbt cannot know. The purple return arrow is the one that makes this an ontology-first project rather than a documented one.

Processing pipeline

use_case_sync.py — ten stages, dependency order

One command runs every derived artifact in dependency order and reports each stage as ok changed / skip with a reason. The order is load-bearing: columns → annotations → ontology is the whole path from raw data to a served semantic layer, and running ontology where it used to sit still regenerates everything, still reports ok, and describes the previous generation's columns.

What each stage refuses to do

StageRefusalWhy it is a refusal and not a bug
taxonomy refuses An attribute tracing to no declared source column is reported and kept out. Written before anything can check it. Otherwise the output is a beautiful description of a warehouse nobody can build.
columns refuses 295 ambiguous bindings refused; 252 columns pruned from 7 files. An unqualified column with five tables in scope binds to each. Fine for lineage, fatal for a contract.
annotations abstains 49 of 272 columns abstain; a closed domain with no cited source is refused. A wrong enum passes every accepted_values test, because it generated them.
ontology declines Regenerating without sqlglot declines rather than emitting 0 of 91 mappings. The silent version produces the same classes with none of the mappings — a diff that reads as tidying.
seeds skips No manifest, no sqlglot, no reference data → skip with the remedy named. A fresh use-case has no manifest and four of five stages need one.
wren skips + counts A metric with no faithful SQL compilation is skipped and counted in the payload. An approximated definition is a wrong contract that plans successfully.

System architecture

Five layers · 43 scripts · 4 packs

The repository is layered by who reads the output, not by language. An agent reads the harness; a script reads the manifest; a consumer reads an artifact; a test reads all three and refuses to let them disagree.

Layer 5 · Verification — 1,638 tests, 10 workflows

What the suite pins

tests/ — 38 files

  • Every committed artifact is current (--check on each stage)
  • Every resolver bug found while building the parser, by name
  • Every rejected optimisation, so nobody re-derives the table
  • Index and Turtle agree on every model, mapping, and annotated column

How it runs

python -m pytest -q

Parallel across cores where pytest-xdist exists, serial where it does not — 97s → 34s measured. Grouping is correctness, not tuning: three files share one xdist group because they mutate the same .sql and the same artifact, and on separate workers each finally restored the other's probe.

Context tier — the layer that keeps all of this affordable

graphify

inbound repo context

Structural questions are answered by a BFS query against the graph, not by reading files. The dbt DAG is merged in from manifest.json, because graphify has no SQL parser.

RTK

Bash output filtering

A PreToolUse hook rewrites shell commands through filters that drop passing steps and keep failures. dbt has none, so refresh.sh routes it through rtk err.

TOON

serialisation, where measured

Uniform record lists only. Routed: lineage edges −41%, drift findings −31%. Rejected: everything whose output is already a handful of counts — a format cannot rescue an unbounded dump.

Features

Functional · non-functional

Functional

what it does

  • Connector onboarding — scaffold, convention check, contract check, alignment verdict, with no warehouse and no profile
  • Column-level lineage to the raw source column, through select * passthroughs and union branches, naming every transform crossed
  • Adapter drift detection — the failure that only appears when two connectors are enabled at once
  • Ontology publication — Turtle for the graph, index.json for the server, prose for the agent
  • Model extraction — the 19 business models the ontology declared and the project never built
  • Model evaluation — each generated model built on DuckDB from sample seeds and interrogated against what the ontology promised
  • LM-assisted proposals where derivation legitimately stops, as proposals that a human promotes

Non-functional

how it behaves

  • Standard library by default. Every optional accelerator is guarded; its absence degrades a run rather than failing it
  • No credentials anywhere. Lineage parses raw_code, not compiled SQL, because dbt compile needs a live warehouse
  • Deterministic by construction. The skill-map wrapper rejects all four LLM verb families; a test fails if one is ever added
  • Incremental and exact. Cache keyed on dbt's own checksum — 1.6s cold, 0.35s warm across 359 models
  • Nothing run-dependent in an artifact. Cache counters and timestamps made files change when the project had not, so --check was permanently red
  • Unavailable is not failed. Exit 3 and a recorded skip wherever an optional toolchain is missing

What the model eval found that nothing else could

label-mismatch

invisible to dbt, to the checker, and to a reader

The ontology publishes Visma eAccounting; the union writes Visma e-Accounting. An agent filtering by the published name gets zero rows and no error.

ambiguous-sql

a portability defect, found sideways

Ambiguous reference to column name "Date". BigQuery resolves an unqualified column with several tables in scope; DuckDB refuses. The same ambiguity that made a source contract claim columns nobody established.

19 cases · 4 scored · 2 passed · 2 failed · 15 reported-not-scored. The first run scored 1 of 19 — sixteen of those failures were in an upstream staging model the generated one merely depends on. Blaming the generator for an absent CSV is how an eval stops being believed.

Deployment

Submodule · activation · gates · egress

The repository is designed to be adopted by a parent repository as a submodule and to behave identically there. Nothing in the derivation path needs a warehouse, a profile, or a key.

The four commands that regenerate everything

./scripts/activate_skill_stack.sh dbt-skills wren-skills   # pack → agent-loaded paths
./skill-packs/dbt-skills/use-cases/<slug>/artifacts/refresh.sh  # manifest + fragment + checks
python3 scripts/use_case_sync.py --use-case <slug> --graphify-update
python -m pytest -q                                     # 1,638 tests, ~34s

Delivery discipline

Branching

stacked, path-scoped

<type>/<ticket>-<lane>-<topic>-<NN>-<layer>, at most four layers, generated artifacts in the top layer only. Never a direct commit to main.

CI

10 workflows

Six call sites run python -m pytest -q — that exact command. The artifact gates are the test suite itself, so a stale committed artifact fails the build rather than a separate step.

Egress

explicit confirmation required

wren genbi deploy ships app bundles — possibly including snapshot data — to a hosting provider. That is data egress: never run without the user's explicit, per-deploy confirmation.

Proving it locally, with no Docker and no keys

./skill-packs/wren-skills/demo/run_wren_demo.sh re-proves the semantic tier end to end: 13 models, 3 relationships, 8 metric views, validate clean, and revenue = 277,183.41 — the filtered metric, not the 289,470.66 raw measure the earlier cube projection shipped.
